# EXE Packaging Plan

Implementation plan for distributing CatalogMatch as a standalone executable.

## Current State (ZIP Distribution)

- `scripts/package_client.py` creates `CatalogMatch_Client.zip`
- Ships the full source repo (minus .venv, __pycache__, etc.)
- Ships a pre-populated `product_matching.db` with test data (Windows paths baked in)
- Client must: install Python 3.12 → run `setup_gpu.py` → clear DB → start using app
- `product-matcher.spec` exists but is not actively used yet

## Target State (EXE Distribution)

- Single folder: unzip → run `ProductMatcher.exe` → done
- No Python install required on client machine
- Empty seed DB ships with the app (no stale test data to clear)
- ngrok bundled optionally (no separate install)
- CLIP model downloads on first launch (not bundled — saves ~350MB)

## Why EXE, Not Docker

- PyWebView requires a native desktop window — Docker has no GUI on Windows without painful workarounds
- GPU passthrough in Docker on Windows is rough, especially AMD ROCm (basically unsupported)
- Docker Desktop is ~4GB install — heavier than the current setup
- PyTorch GPU detection (`setup_gpu.py`) needs direct hardware access
- This is a desktop app, not a headless server

## Database Strategy

### Problem

`init_db()` in `database.py` can fail silently on fresh installs because:

1. `RotatingFileHandler` in `app_core.py` writes logs to `<install_dir>/backend/logs/`. If that path isn't writable (e.g., `C:\Program Files\`), it crashes the import chain **before** `init_db()` runs.
2. `init_db()` itself has no try/except — any failure propagates unhandled.
3. Logs and `.app.lock` write to the install directory instead of `%APPDATA%` in bundled mode.

### Solution: Ship a Seed DB

Instead of fixing `init_db()` startup reliability, ship a pre-built empty database:

- Generated by `scripts/create_seed_db.py` → `backend/seed/product_matching.db`
- Contains all 8 tables, 20 indexes, WAL mode — zero rows
- 136 KB, cross-platform (works on Windows, macOS, Linux)
- No file paths or OS-specific data baked in
- The PyInstaller build copies it to the app data directory on first run

`init_db()` remains in the codebase as a safety net (all `CREATE TABLE IF NOT EXISTS`), but the seed DB means it's effectively a no-op.

### Regenerating the Seed DB

```bash
python scripts/create_seed_db.py --verify
```

Run this whenever the schema changes in `database.py`. The script uses only stdlib (`sqlite3`) — no project dependencies needed. Can run in any Python 3.8+ environment.

## CLIP Model Strategy

### Do NOT bundle the model in the EXE

- The CLIP model (`clip-ViT-B-32`) is ~350MB — same weights regardless of GPU/CPU
- `setup_gpu.py` already downloads it during setup (line 510)
- `SentenceTransformer('clip-ViT-B-32')` auto-downloads on first use as fallback
- Clients need internet anyway (for ngrok), so download-on-first-launch is fine
- Remove line 33 from `product-matcher.spec` (the `~/.cache/clip-models` bundle)

### First-launch UX

Add a progress indicator in the UI when the model is downloading for the first time (~1-2 min depending on connection). The backend already handles the "not cached yet" case gracefully.

## GPU / PyTorch Strategy

### Problem

PyTorch is GPU-specific — different wheels for AMD ROCm, NVIDIA CUDA, Intel, Apple MPS, and CPU. A single EXE cannot include all variants.

### Options

| Approach | Pros | Cons |
|----------|------|------|
| **A: CPU-only EXE** | One universal build, smallest size | No GPU acceleration (5-20 img/s vs 150-300) |
| **B: Per-GPU builds** | Full GPU speed | 4+ separate builds to maintain |
| **C: CPU EXE + GPU setup script** | Universal EXE, optional GPU | Two-step for GPU users |

### Recommended: Option C

1. Build the EXE with CPU-only PyTorch (smallest, most portable)
2. Include `gpu/setup_gpu.py` in the bundle
3. GPU users run `setup_gpu.py` once after install — it detects hardware and installs the right PyTorch wheel into the app's environment
4. CPU fallback always works out of the box

This matches the current ZIP workflow but removes the "install Python" step.

## ngrok Strategy

### Current

- ngrok must be installed separately on the client machine
- Code already supports bundled ngrok at `third_party/ngrok/<platform>/ngrok[.exe]`
- `_resolve_ngrok_binary_path()` checks: env var → bundled path → system PATH

### For EXE

- Drop `ngrok.exe` into `third_party/ngrok/windows/` before building
- The `.spec` file already includes it (lines 9-22)
- Eliminates separate ngrok install for the client

### Optional: Static ngrok domain

ngrok free tier includes 1 free static domain. Adding support would mean:
- URL stays the same across tunnel restarts
- QR code never changes
- One extra field in CONNECT PHONE modal for the domain

## PyInstaller Build Steps

### Prerequisites

```bash
pip install pyinstaller
python scripts/create_seed_db.py --verify
# Optional: place ngrok.exe in third_party/ngrok/windows/
```

### Spec File Updates Needed (`product-matcher.spec`)

1. **Remove** CLIP model bundling (line 33):
   ```python
   # REMOVE this line:
   (os.path.expanduser('~/.cache/clip-models'), '.cache/clip-models'),
   ```

2. **Add** seed database:
   ```python
   datas=[
       ('backend/static', 'backend/static'),
       ('backend/seed/product_matching.db', 'backend/seed'),
   ],
   ```

3. **Add** GPU setup script (for optional post-install GPU setup):
   ```python
   datas=[
       ...
       ('gpu/setup_gpu.py', 'gpu'),
       ('gpu/benchmark_gpu.py', 'gpu'),
       ('scripts/download_clip_model.py', 'scripts'),
   ],
   ```

### First-Run Logic (needs implementation)

On first launch, the app should:
1. Check if `%APPDATA%\ProductMatcher\product_matching.db` exists
2. If not, copy `backend/seed/product_matching.db` from the bundle to AppData
3. Proceed normally — `init_db()` is a no-op since schema already exists

### Build Command

```bash
pyinstaller product-matcher.spec
```

Output: `dist/ProductMatcher/` folder containing the EXE and all dependencies.

## Known Issues to Fix Before EXE

| Issue | Severity | Description |
|-------|----------|-------------|

| Lock file location | Low | `.app.lock` writes to install dir. Move to AppData in bundled mode. |
| No first-run seed copy | Blocker | Need logic to copy seed DB to AppData on first launch. |
| CLIP model bundled in spec | Cleanup | Remove line 33 from `.spec` — model downloads on first use. |

## Client Experience

### First Install
1. Unzip `CatalogMatch.zip` (or run installer)
2. Run `ProductMatcher.exe`
3. App copies seed DB to AppData, starts up
4. CLIP model downloads in background (~1-2 min, progress shown)
5. Ready to use

### With ngrok (one-time)
1. CONNECT PHONE → paste token → SETUP TOKEN
2. AUTO NGROK → share URL + PIN

### Daily Use
1. Run `ProductMatcher.exe`
2. CONNECT PHONE → AUTO NGROK → share URL + PIN

### Optional GPU Setup
1. Run `gpu/setup_gpu.py` from the install folder
2. Restart app — GPU acceleration active
